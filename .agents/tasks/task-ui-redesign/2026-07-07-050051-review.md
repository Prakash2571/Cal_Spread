# Dark trading-terminal palette and glassmorphism pass

A CSS-only redesign of the Calspread dashboard, replacing the previous dark theme with a tighter navy/charcoal palette (#0b0e14 base), glassmorphism card borders, and teal/red signal colors. One line in index.html adjusts the theme-color meta tag. No component logic, API calls, or TypeScript files were modified. All existing CSS class names are preserved, so the component layer compiles unchanged.

Watch for: Premium/discount indicators now share colors with positive/negative signals (confirmed), collapsing previously distinct visual semantics into two colors instead of four. Reduced font sizes and padding across the board improve density but will need real-device verification on small phones where the 480px breakpoint already uses 10–11px type.

## High-level view

The palette shifts from purple-blue accents (#6d8bff / #9b6dff) to a single-hue blue system (#3b82f6 / #60a5fa) paired with a cyan secondary (#06b6d4). Two new CSS custom properties (`--glass`, `--glass-border`) provide a subtle frosted-card effect. Borders switch from opaque hex colors to low-opacity rgba whites, making panels feel less boxed-in.

Premium/discount semantics lost their independent color identity: `--prem` is now identical to `--pos` (#00d4aa) and `--disc` is identical to `--neg` (#ff4757). In the old design, premium was a distinct blue (#3d8bfd) and discount was amber (#ffa63d), giving traders four distinguishable states at a glance. The new palette reduces that to two. This is the most consequential behavioral change in the redesign despite being only a CSS variable swap.

Typography and spacing uniformly shrink by 1–2px and 2–4px respectively, increasing data density. At the 480px breakpoint the cumulative shrink puts several text elements at 10–10.5px, which may fall below comfortable legibility on low-DPI Android phones.

The responsive breakpoints (1180/720/480px) are unchanged, but padding and gap values within each tier are slightly reduced. Touch targets at the smallest breakpoint (brand-mark 34×34, chips with 2px 5px padding) sit below the 44px iOS/WCAG guideline.

## Premium/discount signal collapse

The `pdClass()` function in `format.ts` returns `"prem"` for positive spread values and `"disc"` for negative ones. These map to `.chip.prem` and `.chip.disc` in the stylesheet, which in the old design rendered as blue (#3d8bfd) and amber (#ffa63d) respectively — distinct from the green/red used for general positive/negative values elsewhere in the UI.

After this change:

```
--pos:  #00d4aa     --prem: #00d4aa    (identical)
--neg:  #ff4757     --disc: #ff4757    (identical)
```

The "Prem/Disc" column in each stock card, the spread badge in the card header, and the per-leg P&L colors in the trades modal all lose their independent hue. A trader monitoring 20 cards simultaneously can no longer use peripheral color to distinguish "this contract is trading at a premium" from "this value went up" — they must read the column header or the sign.

This reduces information density for the specific use case this dashboard serves: calendar spread traders who rely on premium/discount signals. Restoring two non-pos/neg accent colors for `--prem` and `--disc` would preserve the clean aesthetic while retaining the four-state palette.

## Typography density at small breakpoints

At the 480px breakpoint the cumulative font shrink puts `.chip` at 10.5px, `.trade-meta` at 10.5px, and `.leg-tag` at 9px. The existing table layout uses `table-layout: fixed` with explicit column widths (15% / 23% / 23% / 23% / 16%), which prevents content overflow but will truncate longer contract names if the text doesn't fit at these sizes. Worth testing on a real 360px-wide device — if contract names clip, bumping the table font to 11px at this breakpoint would fix it without losing much density.

## Border token split

Most card-like elements use `var(--glass-border)` (8% opacity) for their border, but `.oi-panel`, `.trade-card`, `.trade-row`, and several internal dividers still use `var(--border)` (6% opacity). The two tokens are very close in value and the distinction may be invisible on most monitors. If they're intended to be the same tier of emphasis, consolidating to one token would reduce maintenance surface.
